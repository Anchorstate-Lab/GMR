# 「我们的失败」两半都要枚举齐

`ReasonClass` 是基底拿去动作的粒度，`FailureCode` 是人拿去诊断的粒度。
两个都留着，是因为它们服务的对象不同。

**两半必须对称。** 一份日志如果记了七种探针失败、一种规则失败，它描述的是
工具的开发史，不是锚的历史 —— 哪一半被认真对待过，从枚举的长短就看得出来。

`reason()` 是从 code 推出来的，不是并排存的，这样两者不可能各说各话。

## 变了要问什么

新增的 code 属于哪一半？如果只往「探针失败」那半加，停下来看看规则失败那半
是不是也该细化。不对称本身就是信号。
