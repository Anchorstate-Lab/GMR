# GMR 架构

---

## 0. 是什么

> **一个让主观记录挂靠在客观可重算的观测上、并在世界沿作者声明的方向变化时把它重新交出来的运行时。**

```
保证   记录不会沿作者声明的方向与世界脱节而无人知晓
不保证 沿未声明的方向。系统不出声
```

这个限定是设计的**第一风险**,不是免责声明。作者是否声明对了方向,决定这个系统有没有用。记忆在现实中的失效模式恰恰是"沿当初没想到的方向脱节了"。GMR 把这件事从**隐式且无记录**变成**内容寻址、可审计、有修订历史**——这是它的贡献,但它没有消除这个问题。

### 什么值得被锚定

> **锚在事实约束判断、但不决定判断的地方。**
>
> - 事实完全决定判断 → 不要锚。跑一次就知道,记录是纯冗余
> - 事实完全不约束判断 → 锚不住。退化成纯散文存储
> - **事实约束但不决定** → 锚在这里

接口签名约束"密码在服务边界内哈希"这条契约,但不决定它——签名不变,实现照样可以违反。**这条缝隙就是判断必须存在的理由,也是记忆必须存在的理由。**

### 确定性不是客观性

「同插件 + 同目标 ⇒ 同观测」对任何纯函数恒真。它买到的是**确定性**,不是正确性。

基底里没有来源信任分级,但信任没有被消除——它搬到了"谁写的插件、谁选的目标、谁写的转换条件"里。那些地方基底看不见,**不在基底的账上,但仍在系统的账上**。

## 1. 三层

```
记忆层    主观记录的引用。内容住在外部提供方,GMR 不复制
   │ 挂靠(m:n)
锚定层    一台状态机。GMR 的全部实质在这里
   │ 观测
事实层    外部世界。GMR 不存储、不摄入、不维护覆盖率
```

**引用严格单向**:记录 → 锚 → 事实。基底拒绝反向引用。

---

## 2. 锚定层是一台状态机

```
δ(state, obs, taken_at, entered_at) → state'
```

| | |
|---|---|
| `state` | 锚的当前状态。装两样东西:**探针位置** · **域自己的累积量** |
| `obs` | 插件这次吐的状态向量 |
| `taken_at` | 这次观测发生的时刻 |
| `entered_at` | 当前状态被进入的时刻 |
| `state'` | 新状态。与 `state` 不等 = 一次转换 = 一条边沿 |

**两个时钟读数不能合并成一个。** `taken_at − entered_at` 是"在当前状态里已经待了多久",这个量只有两个独立时刻同时在场才问得出来——合成一个"时间",转换条件就再也表达不了停留时长,"陈旧多久算陈旧"这类判据无处安放。

**state 对基底不透明,但不是黑盒。** 精确含义:基底能寻址它的结构,但不解释任何字段的含义。基底取得出某个字段,不知道那个字段是什么意思——就像它能取出观测里的某个值,却不知道那个值代表签名还是价格。

### 位置住在 state 里

**探针位置是状态的一部分,不是插件的输出。** 域设置探针看哪儿;插件去看;看到的东西回来更新状态,其中就包括"我们现在盯着哪儿"。

这一条塌掉了三套本来分家的机制:**挪参照值**、**换观测位置**、**换派生规则**——它们分家的唯一原因是基底看不见位置。位置进了 state,三者都只是**一次状态转换**。

### 转换表

转换条件写成规则表,不是一个大表达式。**第一条匹配即生效。**

```
守卫条件  →  新状态
守卫条件  →  新状态
终结态集合
```

这就是状态机的转换表本身:可读、可 diff、可逐条修订。改一条 = 一次带密封理由的修订,读的时候看得见改了哪一条。

### 终结由基底兑现

锚上声明哪些状态是终结态。进入终结态后,基底**停止调度,并拒绝此后一切写入**——不只是转换,也包括改状态、改判据、改终结集合本身。

**不可逆是结构,不是判断。** 靠域在转换条件里自觉守的不变量等于没有不变量——一个写错的条件就能让它回去,而日志里看不出这是 bug 还是有意。

**「终结过」是日志里发生过的事,不是对最后一个状态的一次重新解释。** 这两者的差别不是措辞。按后者算,任何把状态挪出终结集合的动作都能静默复活这个锚,于是读的人必须先问「它以前终结过吗、后来谁动过终结集合」才敢用这个答案——终结就不再是一条能依赖的结构事实,只是当下这一次解释。

### 判据写错了:开新的一代,不是拽回旧的

终结不可撤销,所以纠错的出路是**接替**:开一个新的锚,声明它接替哪一个已经终结的锚,理由随之密封。旧的那一代永远是关的。

**代价说清楚:接替不迁移任何东西。** 挂在旧锚上的记录不会自己跟过来,历史也不会合并。换来的是消费方永远不必处理「复活」这一类边沿,而「这个判断当初按什么判据下的」始终指向一份不会被改写的日志。

终结是基底唯一解释的语义。其余全部被计算、被记录、被通知,**不被据以做任何决定**。

## 3. 三方分工

| | 给什么 | 形态 | 版本 |
|---|---|---|---|
| **基底** | 状态槽 · 转换记账 · 调用插件 · 日志 · 密封 · 终结兑现 | 代码 | 求值器版本 |
| **插件** | 位置 → 状态向量 | **内容寻址的可执行物** | **哈希,挣来的** |
| **锚** | 在乎哪些方向 · 转换表 · 终结态集合 | **数据,可读可 diff** | 改它 = 一次带理由的修订 |

**表示归插件,注意力归锚。** 插件吐出全部它能看见的方向;锚声明这个锚在乎哪些、什么条件算转换。同一个插件因此能服务关注点不同的多个锚,不必为每个关注点重编译。

**注意力必须是数据,不能是黑盒。** 改锚上的转换表,读的时候能看见"从什么改成什么",修订带密封理由;改插件,基底只看得见哈希变了,看不见变了什么。而"这个锚在乎什么"恰恰是事后最需要审的东西。

## 4. 三段边界

划清"基底规定死"、"基底提供的语言"、"域完全自由"三段,是这套设计能不能长期不腐坏的关键。

### ① 基底规定死 —— 域没有选择

```
插件的输入          位置。**域给的** —— 它是「去看哪儿」
插件的输出契约      一个可判等的状态向量
插件的失败契约      怎么表达「我没看成」—— 与「我看了,那儿什么都没有」必须可分
转换函数的签名      δ(state, obs, taken_at, entered_at) → state'
求值失败的处置      转换条件炸了 → 不转换 + 发边沿。域无权决定"这次就算了"
终结的兑现          进入终结态后拒绝一切后续写入。域无权反悔
```

第四条不能交给域:**域没法处理"自己的表达式炸了"这件事。** 这是"系统里不允许存在既不成条目、也不发边沿的路径"的落点。

**我们的失败和世界的失败不共用一个计数器。** 世界这会儿够不着值得重试,攒够一串才算停摆;转换条件炸了是判据本身写错了,重试一万次也不会好——它**第一次就要出声**,退避直接拉到上限。把两者合并,等于让一个写错的规则安静地混在"最近网络不太好"里。

**「去看哪儿」和「实际在哪儿」是两个量,不要混成一个。** 输入侧的位置由域给,基底只从状态里那个槽取值。输出侧探针可以回报它实际的落点——那是观测里一个普通方向,和别的方向没有区别。

禁止后者会把 §5「位置该是模糊坐标」整节掏空:那节的全部价值是「位置没对上、别的对上 ⇒ 搬家了,该把位置挪过去」,而要挪过去,就得有人说出挪到哪。

**基底仍然不解释它。** 落点回来之后是域的事:域写一条转换规则把它写进新状态的位置槽,或者不写。基底自始至终只知道有位置这个槽,以及去哪儿取它。

### ② 基底提供的语言 —— 是规范,不是语义

路径取值 · 比较 · 逻辑 · 算术 · 空值判定 · **对象构造**(转换条件要吐出完整的新状态)。

「哪些方向变了」以**语言算子**的形式提供,不是基底每次替域算好一个差集存进日志。域用它是在用语言,就像用加号——**基底提供算子,不解释值的含义**。

**语言必须保持小**:纯、可终止、无 IO、无时钟、无随机。没有读时钟的能力,否则同一份日志重放两次得到不同结果,整条可重算链当场作废。时间只来自观测字段或日志已记录的时刻。

复杂的判定归**插件**——它可以任意复杂,因为它的版本是哈希锁死的。**能算的搬进插件,只留判定给转换条件。**

### ③ 域完全自由 —— 基底一个字都不说

状态里装什么 · 状态叫什么名字 · 什么条件算转换 · 插件内部怎么实现。

**没有固定的状态词表。** 一个域的"漂移"可逆自愈,另一个域的"结算"不可逆终结——它们没有共同的状态机。基底若定死一套词表,第一个域的语义就进了基底,第二个域只能伪装成第一个的形状。

## 5. 插件

**插件的身份是它语义闭包的内容哈希。它以什么形式被调用——进程内 · 子进程 · HTTP——是传输的事,不是身份的事。**

**版本必须挣得来,不能靠声明**——一个内容哈希不可能撒谎,一个手写的版本串可以。这条是整个可追责链的地基:少了它,日志里存着的状态就无法判断是"当时算出来就是这个"还是"后来插件改了逻辑",而这两者的处置完全相反。

但"挣得来"只说了一半。身份要成立,必须**双向**:

```
身份变了  ⟺  行为可能变了

行为变了、身份没变    撒谎。这是"插件改了逻辑而版本没动"
身份变了、行为没变    噪音。没有任何消费方能把它滤掉
```

所以哈希的对象必须**不多不少是能改变输出的那些输入**:抽取逻辑的源码、它据以解析的库的版本号、输出契约。

- **过松**(漏掉依赖的版本)→ 换一个解析器后端,版本纹丝不动
- **过紧**(哈希二进制的字节)→ 平台、编译器、构建的非确定性全成了"逻辑变化"

两种错误同样致命,而后者还多一重代价:字节哈希是本机的,两台机器对同一个世界给出的 `fact_address` 永远对不上,**日志因此不可能跨机器合并**。语义闭包哈希天然跨平台,那条路才留得住。

**这不取消"版本由执行的那一方给出"。** 声明只说要哪个名字;那个名字在这台机器上站着什么、闭包全不全,只有执行的那一方知道。

**两件事不要混:**

```
派生身份    这次观测是哪份逻辑产出的    语义闭包哈希      读日志的人,几年后
供应链完整  手上的二进制是不是那份逻辑  签名 / 包管理器   装它的那一刻
```

第二件是每个软件都有的问题,用每个软件都在用的办法解。基底不为它自造一套制品库。

**基底不沙箱插件。** 碰网络碰时钟的插件不是被拦住,是重放时露馅。

### 位置该是模糊坐标

位置是域定义的类型,基底不解释它。但有一条经验要写下来,因为它是从实测里
撞出来的:**位置应该是模糊坐标,不是精确地址。**

精确地址(行号、完整路径、结构序号)在第一次改动后就失效,而代码本来就会
动。模糊坐标(若干项各自可选)配上「报告哪几项对上、哪几项没对上」的匹配,
让同一次观测同时回答三个问题:

```
名字没对上,别的对上   东西还在,改名了
位置没对上,别的对上   搬家了 —— 该把位置挪过去
签名没对上,别的对上   契约变了
全都没对上            真没了,或者变得认不出来
```

**腐坏的类型由「哪几项没对上」直接读出,不需要额外的探针。** 扫全量的探针
做不到这一点:它只知道集合变了,要知道「同一个东西改了名」得算两个数组的
差集,而探针看不到历史、转换表也没有集合运算。

这是**给探针作者的建议,不是基底的规定**。基底仍然只认识「有位置这个槽」。

### 可证伪性完全依赖目标可重取

```
目标内容寻址且不可变   →  成立。重跑必得同一答案,不同即分歧
目标会变              →  不成立。"答案不同"有两个无法区分的解释:
                         插件不纯,或世界变了
```

**不可重取是常态,不是边角情形。** 所以绝大多数情况下,一条观测记录不是一份可复核的推导,是**一台机器在某一刻的封存证词**。它的证据力全部来自:观测原样存在条目里、版本号一并存、日志只增不改、密封不可篡改。这四条都是真的,且都跟目标可不可重取无关。

**基底不标注可证伪性,也不声称它。** 那住在插件的声明里,而声明可以撒谎。跟处理信任同构:搬走了,不是消除了。

日志里那一栏说的是另一件事:**闭包全不全**。

```
Closed   能改变输出的输入全在哈希里
Open     有东西在哈希之外还能改答案,并且说出是什么 —— 宿主环境、解释器、
         远端系统、被问的时刻、住在别处的实现
```

**这一栏问的是闭包全不全,不是身份稳不稳。** 「名字解析到什么,跑的就是什么」是 `Closed` 的一条必要条件,不是它的等价:一个在调用前就确定地解析出身份的传输,照样可能开放——它每次去问一个远端系统,答案由那边和此刻决定,而这两样都不在哈希里。反过来,身份不稳的传输一定开放,因为「跑的是什么」本身就不在哈希里。

所以这一栏**由传输给,而且只有知道自己在执行什么操作的传输才给得出答案**。执行一个已知操作的传输可以推导它——取一个 URL 必然开放于远端与时刻,读一个声明好的本地路径不开放于任何东西。而执行外来闭包的传输推导不出来:它没读过那段代码,替它作答就是替看不见的代码打包票。这种情况下答案必须由注册方随闭包一起交进来。

`Open` 必须说出开放在哪。一个不带内容的 `Open` 说了句子却没说是哪一句,而「解释器从 `PATH` 解析」和「远端可能宕机」不是同一种风险——事后想区分就再也分不出来,因为那个区别从来没被记下来。

### 派生规则升级的爆炸半径

任何一跳的派生规则变了,状态都可能在世界毫无变化的情况下全系统翻转——插件换了输出结构,或求值器换了比较语义,效果完全一样。

这不是能靠数据结构消除的,只能靠**记账 + 预案**:每条条目记下当时的三重身份,消费方据此识别"这批翻转来自规则升级,不是来自世界"。**记了版本却没有这条预案,等于修了记录、没修爆炸。**

```
声明    锚上写的「我要哪个插件、什么参数」   —— 它可以和现实不符
派生    实际算出这些事实的东西               —— 只有执行的那一方知道
求值器  当时那套比较与构造的语义
```

**三者不许合并。** 它们独立演进,出错方式不同,合并任何两个都会在其中一边撒谎。尤其是前两个:把声明当成派生的身份,正是"插件改了逻辑而版本没动"这个失效模式的入口——而那恰恰是版本要挣得来的全部理由。

**版本由执行的那一方给出,不由锚自己算。** 锚只能声明它想要什么;声明会撒谎,执行不会。

## 6. 记忆层

**GMR 只存引用与绑定时那一版的标识,不复制内容。** 内容住在外部提供方,靠提供方按版本取回。

**对提供方的要求分两级。**

```
承重墙(缺一不可)    稳定 id · 按 id 取回 · 可判等的版本
能力(可缺)          按版本取回
```

少了可判等的版本,"记录被改写了"这条状况直接报不出来,GMR 对记忆的那半个价值归零——所以它在承重墙里。

**按版本取回不是准入要求。** 它的全部产出只喂报告:读取时能不能把"从什么改成了什么"摆出来。它不进状态机、不进日志、不影响任何退出码。GMR 的主循环是"代码变了 → 锚报漂移 → 交还记忆给人重判",这条循环里它一次都不参与。缺了它,人照样被叫醒重判,只是要重读全文而不是读 diff。

**能力由"实现了哪个 trait"表达,不由一个所有人都要处理的返回值变体表达。** 没有历史的提供方不实现 `History`,调用点因此根本拿不到那个方法——而不是拿到一个说"我没有"的答案。例外不进类型,不渗透进任何消费点。

**外部记忆库的历史与 git 的历史不是同一种东西。** git 的不可变、内容寻址、本地,取回版本 X 是纯函数;外部库的派生、可变、远程,取回是一次可能失败的 RPC,且**没有一个承诺保留**——mem0 写入即可设过期,级联删除会带走被取代的那一层。所以 `fetch_at` 拿不到那一版,含义是"这一版没被保留"——**世界的答案**,而不是提供方缺能力。

**这四条各自的兑现物写在一致性套件里,不写在这里。** 这一段之所以要重写,正是因为原来的四条要求从来没有任何机械检查在兑现:一句实现备注被"零注释"规则搬成锚定记忆之后,读起来就像一条设计决策,而没有任何东西能分辨这两者。

**绑定说"关于什么",订阅说"什么时候"。**

```
绑定    这条记录是关于这个锚的        关于什么
订阅    我关心哪些转换               什么时候
```

绑定不该承担订阅的职责。把"什么时候才交出这条记忆"塞进绑定,绑定就变成了带条件的订阅,而条件又要问"是数据还是代码",再套一层。信噪比问题的解法在订阅侧。

**绑定是基底的原语,订阅不是。** 基底知道"这条记录挂在哪个锚上"并把它作为一等结构维护;"我关心哪几维、条件怎么写"完全是域自己的声明与解释,基底既不提供订阅机制,也不规定订阅的形状。这与 §4③ 同构:转换条件属于域,"这条记忆什么时候该被交出来"同样属于域——基底只保证绑定这一半的结构完整。

**记录之间的链接被携带,不被执行。** 一条记录的状态不依赖另一条记录的状态。传播语义在不同场景可以完全相反,不该由基底选。

**同锚共存**(两条记录挂在同一个锚上)是从绑定派生的**查询**,不是存储——它不可能是幻觉,因为它是两份记录各自选择了同一个可观测对象这件事的结构后果。

**接地不沿链接传播。** 无锚记录允许存在,它们靠遍历被捎带,但拿不到任何保证,读取时必须标注。

## 7. 边沿

**事件和状况不是一回事,不要摆在同一格。**

```
事件（日志里发生过的）        转换 · 终结 · 连续看不成
状况（此刻仍然成立的）        陈旧 · 记录被改写了
```

基底不发明"升级""告警""优先级"。它只让"我上次看之后,哪些锚转换到了哪些状态"可以被廉价地问出来。

事件有游标:问过就不再交第二次。**状况没有,而且不可能有** —— 陈旧是拿当下的钟去比对最后一次看见,改写要向提供方问"现在是哪一版",两者都不在日志里,日志游标因此表达不了"这条我看过了"。

把状况塞进事件那一格,代价不是不优雅:每一次轮询都会重新报一遍同样的东西,而消费方无从分辨这是新发生的还是老样子——**于是"上次之后"这个契约对所有类别一起失效了**。所以它们分开摆,并且明说状况按内容去重,不按游标。

**事件驱动部署仍需一个最小心跳来检测停摆。** 没有轮询就没有东西去发现缺席。这是固有代价,不能靠数据结构消除。

## 8. 存储

按可变性分。写入频率、一致性要求、崩溃语义没有一条相同,合成一个接口就等于逼实现方给只增不改的日志开后门。

```
日志      只增不改。写入声明它折算自哪一条     非有不可
绑定库    只增不改。引用 x 锚点的纯关系         非有不可
密封库    内容寻址 blob。修订/关闭的理由存证    非有不可
运行参数库 可变,不追加历史,不密封             非有不可
目击库    可变。每个锚被看过几次 · 最后一次何时   非有不可
链接库    只增不改。引用 x 引用的记忆间关系      可选
队列      可变。到期 · 租约 · 失败计数          可选:仅轮询部署
```

**目击不是日志的一部分,尽管它数的是观测。** 日志记的是「发生了什么」,每一条不可改;目击库记的是「看过几次、最后一次何时」,是一个就地重写的计数器。把它塞进日志,等于让一次「什么都没变」的观测也追加一条条目,而日志的全部价值是每一条都对应一次真正的转换。

右边那一栏说的是**部署**需不需要,不是这一样东西属于哪一层;`CLAUDE.md` §5 那份清单说的是后者,所以链接库与队列在那里和其余五样并列,两处不冲突。以上七样都是**契约**:它们各自定义了「一个存储在这件事上必须做到什么」,一个部署可以用不上链接库,但没有哪个存储能一边实现它一边不遵守它。

与契约并列还有一层——**能力**。存储可以不实现,而不实现本身就是回答,不是被迫答一句「我没有」。

```
链条自证   给得出「链在哪一条断了」,给不出就是这个后端答不了这个问题
```

判定一样东西属于哪一层,只问一句:**一个存储能拒绝它、并且仍然是一个完整的存储吗?** 一个不会自证链条的日志仍然是日志;一个不会追加的日志不是。

**运行参数与判据不是同一类变率,不能挤进同一张表。** 节奏、保留期这类字段不参与任何转换判断——重写它们不重开任何已经做过的判断,所以存储它们的接口理应可变、不追加历史、不密封。把这类字段塞进日志或绑定库,就是逼一个无害的重写去背判据存储的不可变式;分开存,两边的不变式才各自成立。它与队列的差别在于**内容**而非可变性:队列装的是到期与租约这类调度状态,仅轮询部署才需要;运行参数库装的是每个部署都要有的操作旋钮,不可选。

**密封与绑定不共用一个存储接口。** 密封的是修订/关闭理由,是内容寻址的存证,跟"引用 x 锚点"这个关系没有任何共同的可变性或一致性要求——合在一个 trait 里只会让每个绑定库实现者被迫多背一份密封的义务。同理,链接(记忆与记忆之间的关系)和绑定(记忆与锚点之间的关系)是两个不同阶的关系,合并会导致"加一条链接也要重新声明一遍绑定"。

**只增不改由存储层拒绝更新与删除来兑现,不靠自觉。** 基底 ship 接口,不 ship 后端:核心的依赖清单里不得出现任何数据库。

**并发正确性由写入自己携带的前提兑现,不由租约兑现。** 每一条追加都要说出它是从哪一条条目折算出来的,日志比对不上就拒绝。`Entry::Transition` 是 `f(state@H, obs)`,而 `append` 一度从不知道 `H` 是几——签名里没有位置放它。**日志守不住一条从来没有人告诉过它的不变式。**

这一条必须覆盖全部写路径。留一条不声明前提的旁路——哪怕只是给"手工触发一次"用的——就是把担保降级成"大部分时候",而两边的写者互相看不见。**作者的修订也不在例外之列**:一次 `revise` 封存的是由它读到的状态算出来的、不可变的理由,"你写理由的时候锚动了"是应当被告知的事,不是应当被静默覆盖的事。

唯一的例外是**内容不由任何一次读决定的条目**——观测失败的记录:它的次数是折算时现算的、不存在于条目里,两个并发失败各计一次就是对的。判据是一句话——**这条写入的内容,是不是由一次读决定的?**

**租约因此是效率装置,不是正确性装置。** 它的价值是别让两台机器同时打同一个探针、白烧一次网络调用;取不到就让持有者去打。它仍然要求令牌只增不减,但那是为了让日志能如实记下"这一条是在谁的调度声明下写的"——一份凭证,不是一道许可。把正确性寄托在它身上,等于让一个没有部署队列的系统悄悄变成另一个系统。

## 9. 物理结构

```
基底      领域无关。不产二进制
电池      可复用,不属于任何单一域,由域选择装配:传输实现 · 内容提供方实现 · 不认识任何语言的走查与匹配工具
域        插件 · 锚声明 · 记忆 · 装配与命令行
```

**装配就是域的决定。** 选哪个传输、哪个内容提供方、挑不挑用某个电池——这些具体选择一旦写死在基底的产品壳里,那个壳就不再领域无关了,不管它的代码里有没有出现域的词汇。这是最容易被漏掉的一处渗透,因为它看起来像"默认配置"。

**电池这一层存在的理由**:脚本传输、文件内容提供方、模糊坐标的走查与匹配这些能力确实不属于任何单一域(任何域都能用),但也不该被基底强制装配。它们是可选电池,由域来挑,而且这份清单不封顶——任何"多个域都要、但不该长进基底"的能力都够格再开一个电池。

**存储后端不是电池。** 它是承接存储契约的那个基底包**自己**按 feature 切换的实现——加一个后端是加一个 feature 加一个模块,不是加一个包。这跟传输、内容提供方不一样:那两类契约的具体实现故意放在契约包之外,是因为契约本身就打算被基底之外的任何人实现;存储后端留在契约包内部,是因为"只增不改""带写入令牌"这类不变式必须由定义它们的同一个包守住,交给包外的实现方等于把不变式的执行权也让出去。

## 10. 已知代价

诚实列出,不藏。

**1 谁写插件与转换条件(产品存亡级)**
整套接地能力挂在"有人能为这个锚写出正确的插件与转换表"上。**接地的质量上限等于判据作者的水平上限。** 可行路径是提议 + 人确认 + 插件与转换表都内容寻址、可审计、可修订。

**2 用新规则重算旧观测:做不到**
插件链没有可归档的中间物,观测已经是终点。插件升级只能向前生效,历史条目照原样保留、带着当时的版本号。

**3 域要自己数数**
基底不再提供跨观测的派生量(连续计数、上一次的值)。域把需要的累积编码进状态。简单的域因此多写几行,换来的是不会再有基底强加的语义(比如"计数的是观测次数还是时间"这种由基底替你选的口径)。

**4 绑定只有警告,没有拒绝**
锚可以先于它的目标存在,所以引用了不存在的方向只警告。代价是拼错的路径与"目标还没长出来"在开锚那一刻长得一样,都要等运行期才现形。无免费解法。

**5 接地率算不出分母**
被锚的记录数基底数得出,记忆总量住在外部提供方而提供方只有按 id 取回。**基底提供分子,分母由产品补齐;没有产品补分母,这条指标不存在。** 基底能独立看见的是互补的那一头:建了锚却没有任何记录挂上去。

## 11. 文档自我约束

**本文档只写架构决定。禁止写入:具体类型名 / 字段名 / 函数名 / 常量数值 / 文件名 / 调用链。**

那些是代码的唯一真相,写进来就开始腐化——而且腐化的形态很具体:文档描述的接口在代码里不存在,读文档的人(包括下一个 AI)把它当现状,于是照着不存在的东西继续设计。

**也不写验收清单。** 一份自己列的检查表,用它给自己打分,是这个项目已经犯过的错误:每一轮都是"发现洞 → 补那个洞 → 宣布补齐",而分母始终是自己列的。机械可查的约束应该是可执行的检查,不是文档里的条目。

**不写走查例子。** 例子会被下一个人读成清单,而下一个真正有人在乎的方向不会在任何清单上。
